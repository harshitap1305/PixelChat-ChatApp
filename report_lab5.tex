\section{Introduction}
This report details the end-to-end implementation and deployment of a high-performance, Layer 7 HTTP load balancer built entirely in Go using the standard library. The core objective was to distribute client request load across multiple distributed instances of a secure messaging backend application (implemented in Python with FastAPI), ultimately increasing throughput and eliminating single points of failure.

In addition to the Load Balancer, a custom Go-based Concurrent Load Generator was implemented to stress-test the infrastructure. This report covers the exact architectural designs, concurrent programming patterns, port mappings, and deep statistical analysis of the experimental load tests.

\section{System Architecture and Port Mapping Logic}
The lab environment employs a strict and non-standard port forwarding configuration to isolate user deployments on shared servers. Each assigned container is given a dedicated SSH port. All other available application ports are derived mathematically from that SSH port using the formula:
\[ \text{App\_N\_Port} = \text{SSH\_Port} + (N \times 1000) \]

To deploy the architecture cleanly, the following port assignments were calculated and configured:
\begin{itemize}
    \item \textbf{Sys1} (SSH Port 2273) hosts the Load Balancer. We mapped it to \textbf{App2} ($2273 + 2000$), resulting in the load balancer listening on port \textbf{4273}.
    \item \textbf{Sys2} (SSH Port 2274) hosts Backend 1. We mapped it to \textbf{App3} ($2274 + 3000$), resulting in port \textbf{5274}.
    \item \textbf{Sys3} (SSH Port 2275) hosts Backend 2. We mapped it to \textbf{App3} ($2275 + 3000$), resulting in port \textbf{5275}.
    \item \textbf{Sys4} (SSH Port 2276) hosts Backend 3. We mapped it to \textbf{App3} ($2276 + 3000$), resulting in port \textbf{5276}.
\end{itemize}

\textbf{Why App3 for Backends?} The messaging application strictly operates with a default \texttt{PORT=5000} setting. \textbf{App3} provides a base port in the 5000 range, ensuring seamless environmental integration without requiring deep rewrites to the Python backend's internal environment variable schema. Furthermore, the Python messaging application exclusively serves HTTPS traffic utilizing self-signed certificates, which mandated specific configurations in the load balancer to accept unverified TLS connections.

\section{Load Balancer Implementation Details (Go)}
The load balancer acts as a reverse proxy orchestrating traffic. It is fully configurable via Command Line Interface (CLI) flags (e.g., \texttt{-addr}, \texttt{-backends}, \texttt{-timeout}), allowing dynamic reconfiguration without recompiling the binary. The implementation highlights include:

\subsection{Concurrency-Safe Data Structures}
The internal state is split into two primary structs: \texttt{Backend} and \texttt{Metrics}. 
The \texttt{Backend} struct uses an \texttt{atomic.Bool} to track liveness and an \texttt{atomic.Int64} for tracking requests currently "In-Flight." The \texttt{Metrics} struct uses \texttt{atomic.Uint64} for all counters (Total, Success, Failed) to ensure highly concurrent increments from thousands of goroutines do not result in race conditions. Only the Latency tracking slice requires a \texttt{sync.Mutex}, as appending to a Go slice is not inherently atomic.

\subsection{Traffic Isolation and Mux Routing}
To ensure administrative and monitoring traffic does not interfere with client load, Go's \texttt{http.ServeMux} is utilized for strict route segregation. Internal endpoints (\texttt{/lb/health}, \texttt{/lb/status}, \texttt{/lb/metrics}) are handled independently, while the root wildcard route (\texttt{/}) delegates entirely to the \texttt{ServeHTTP} reverse proxy method.

\subsection{Round-Robin Scheduling Logic}
Traffic distribution is handled via a Round-Robin algorithm implemented using an atomic counter (\texttt{lb.next.Add(1)}). The algorithm uses modulo arithmetic (\texttt{index \% uint64(len(backends))}) to cycle through the backend slice. Crucially, the selector checks the \texttt{b.Alive.Load()} boolean; if a backend is dead, it instantly increments to the next one, ensuring traffic is never routed to a known failed node.

\subsection{Active Health Checking (Liveness Probes)}
A background goroutine, \texttt{healthLoop}, fires every 1 second, entirely independent of the request-serving path. It iterates through all backends and issues an HTTP GET to \texttt{/health}. 
\textbf{TLS Configuration:} Because the Python backends use self-signed certificates, a standard HTTP client would reject the connection. The health checker is explicitly configured with a custom \texttt{Transport} featuring \texttt{TLSClientConfig: \&tls.Config\{InsecureSkipVerify: true\}}. If the probe fails or times out, the backend's atomic \texttt{Alive} flag is immediately flipped to \texttt{false}, and terminal logs are emitted.

\subsection{Reverse Proxy and Error Handling}
When a valid backend is selected, the request is handed to Go's built-in \texttt{httputil.NewSingleHostReverseProxy}. The proxy's error handler is overridden: if a TCP connection fails mid-flight, the proxy intercepts the error, flips the backend's \texttt{Alive} status to \texttt{false}, increments the \texttt{BackendErrors} metric, and returns a \texttt{502 Bad Gateway} to the client, preventing the load balancer itself from crashing.

\subsection{Multi-Tiered Timeout Engineering}
To prevent resource exhaustion (goroutine leaks) if a backend hangs indefinitely, strict timeouts are enforced at three distinct network layers:
\begin{enumerate}
    \item \textbf{DialContextTimeout:} Rejects the request if the initial TCP handshake with the backend takes longer than the allowed limit.
    \item \textbf{ResponseHeaderTimeout:} Drops the connection if the backend accepts the connection but fails to return HTTP headers promptly (e.g., the server is busy/deadlocked).
    \item \textbf{HTTP Client Timeout (Context):} The original \texttt{r.Context()} is wrapped in a \texttt{context.WithTimeout} set to 800ms. This acts as an absolute, overarching deadline. If the total processing time exceeds this, the connection is forcefully torn down.
\end{enumerate}

\section{Load Generator Implementation Logic}
To accurately measure performance, a custom concurrent Load Generator was built to bypass the limitations of single-threaded tools like \texttt{curl}.
\begin{itemize}
    \item \textbf{Worker Pool Architecture:} It uses a buffered channel to queue $N$ target requests and spins up a specific number of worker goroutines (controlled by the \texttt{-concurrency} CLI flag). Each worker pulls jobs from the channel, executes an HTTP request, tracks the success/failure state, and records the exact time taken using \texttt{time.Since()}.
    \item \textbf{Percentile Calculation:} The latencies are stored in a slice. Once all workers complete (tracked via \texttt{sync.WaitGroup}), the slice is sorted. The p50 (median), p95, and p99 metrics are calculated by indexing into the sorted array at the $0.50$, $0.95$, and $0.99$ markers, providing a statistically sound view of tail latency.
    \item \textbf{Artifact Persistence:} Following software engineering best practices, the generator automatically formats and persists results. It creates a targeted JSON file per experiment for deep diving, and appends a summarized row to a cumulative CSV file (\texttt{comparison.csv}). It dynamically handles missing files and inserts CSV headers automatically on the first run.
\end{itemize}

\subsection*{Deep Technical Reasoning}

\textbf{1. The Collapse of the Single Backend (Dropout Analysis)} \\
In the single-backend scenario, the dropout rate skyrocketed to \textbf{23.46\%} (1,173 failures). This occurs because 40 concurrent TCP connections were constantly hammering a single Python FastAPI instance. As the Python event loop became saturated, requests began to queue. Because the load balancer enforces a strict 800ms timeout, requests that were stuck in the queue for too long were forcefully aborted, resulting in massive failure rates. 
By expanding to three backends, the concurrency per node dropped from 40 to $\sim13$. The queues were instantly alleviated, and the dropout rate plummeted to \textbf{0.08\%}.

\textbf{2. Tail Latency Recovery (p99 Analysis)} \\
The p99 latency represents the worst 1\% of the requests. In the single-backend test, the p99 was a massive \textbf{1521.0ms}. This represents the requests that were at the very back of the saturated queue but managed to \textit{barely} complete before the connection dropped. 
With three backends, the maximum queue depth was severely reduced, bringing the worst-case response time (p99) down by more than half, to a highly responsive \textbf{711.0ms}.

\textbf{3. Median Shift Anomaly (p50 Analysis)} \\
Counter-intuitively, the median latency (p50) actually \textit{increased} slightly from 286ms to 301ms when upgrading to three backends. This is a classic statistical artifact of high-failure testing: in the single-backend test, the 1,173 slowest requests failed and were therefore \textit{excluded} from the latency tracking (which only tracks successes). Thus, the single-backend's p50 looks artificially fast because it only represents the "lucky" requests that got processed immediately. In the 3-backend setup, 99.9\% of requests succeeded, including the inherently heavier processing tasks, providing a much truer representation of the application's actual median processing time.

\textbf{4. Throughput Saturation (RPS)} \\
The RPS marginally improved from 125.03 to 130.27. This indicates that the absolute physical throughput limit of the testing network and the 40-worker load generator itself was hovering around ~130 RPS. While the total number of requests processed per second didn't skyrocket, the \textit{quality and reliability} of that processing completely changed (as evidenced by the elimination of dropped requests).

\begin{lstlisting}[language=Go, caption=Load Balancer Full Implementation]
package main

import (
	"context"
	"crypto/tls"
	"encoding/json"
	"flag"
	"fmt"
	"log"
	"net"
	"net/http"
	"net/http/httputil"
	"net/url"
	"sort"
	"strings"
	"sync"
	"sync/atomic"
	"time"
)

// ─── Backend ──────────────────────────────────────────────────────────────────

type Backend struct {
	URL      *url.URL
	Alive    atomic.Bool
	InFlight atomic.Int64
}

// ─── Metrics ──────────────────────────────────────────────────────────────────

type Metrics struct {
	Total         atomic.Uint64
	Success       atomic.Uint64
	Failed        atomic.Uint64
	BackendErrors atomic.Uint64

	LatencyMu sync.Mutex
	Latencies []time.Duration
}

// ─── LoadBalancer ─────────────────────────────────────────────────────────────

type LoadBalancer struct {
	backends []*Backend
	next     atomic.Uint64
	metrics  Metrics
	timeout  time.Duration
}

func (lb *LoadBalancer) nextBackend() *Backend {
	n := len(lb.backends)
	for i := 0; i < n; i++ {
		index := lb.next.Add(1) % uint64(n)
		b := lb.backends[index]
		if b.Alive.Load() {
			return b
		}
	}
	return nil
}

func (lb *LoadBalancer) healthLoop(interval time.Duration) {
	// InsecureSkipVerify allows the health checker to reach backends
	// using self-signed TLS certificates (the Python messaging backend).
	client := &http.Client{
		Timeout: 2 * time.Second,
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{InsecureSkipVerify: true},
		},
	}
	for {
		for _, b := range lb.backends {
			resp, err := client.Get(b.URL.String() + "/health")
			if err != nil || resp.StatusCode >= 500 {
				if b.Alive.Load() {
					log.Printf("[health] backend %s -> UNHEALTHY", b.URL)
				}
				b.Alive.Store(false)
			} else {
				if !b.Alive.Load() {
					log.Printf("[health] backend %s -> HEALTHY", b.URL)
				}
				b.Alive.Store(true)
			}
			if resp != nil {
				resp.Body.Close()
			}
		}
		time.Sleep(interval)
	}
}

// ─── Monitoring Handlers ──────────────────────────────

// healthHandler: GET /lb/health
func (lb *LoadBalancer) healthHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
}

// statusHandler: GET /lb/status
func (lb *LoadBalancer) statusHandler(w http.ResponseWriter, r *http.Request) {
	type entry struct {
		URL      string `json:"url"`
		Alive    bool   `json:"alive"`
		InFlight int64  `json:"in_flight"`
	}
	var list []entry
	for _, b := range lb.backends {
		list = append(list, entry{
			URL:      b.URL.String(),
			Alive:    b.Alive.Load(),
			InFlight: b.InFlight.Load(),
		})
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]interface{}{"backends": list})
}

// metricsHandler: GET /lb/metrics
func (lb *LoadBalancer) metricsHandler(w http.ResponseWriter, r *http.Request) {
	lb.metrics.LatencyMu.Lock()
	cp := make([]time.Duration, len(lb.metrics.Latencies))
	copy(cp, lb.metrics.Latencies)
	lb.metrics.LatencyMu.Unlock()

	sort.Slice(cp, func(i, j int) bool { return cp[i] < cp[j] })

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]interface{}{
		"total":          lb.metrics.Total.Load(),
		"success":        lb.metrics.Success.Load(),
		"failed":         lb.metrics.Failed.Load(),
		"backend_errors": lb.metrics.BackendErrors.Load(),
		"p50_ms":         percentile(cp, 50).Milliseconds(),
		"p95_ms":         percentile(cp, 95).Milliseconds(),
		"p99_ms":         percentile(cp, 99).Milliseconds(),
	})
}

// ─── Forward Handler ──────────────────────────

func (lb *LoadBalancer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	lb.metrics.Total.Add(1)
	start := time.Now()

	b := lb.nextBackend()
	if b == nil {
		lb.metrics.Failed.Add(1)
		http.Error(w, "no healthy backend available", http.StatusServiceUnavailable)
		return
	}

	b.InFlight.Add(1)
	defer b.InFlight.Add(-1)

	target := b.URL
	proxy := httputil.NewSingleHostReverseProxy(target)

	dialer := &net.Dialer{
		Timeout: lb.timeout, 
	}
	proxy.Transport = &http.Transport{
		DialContext:           dialer.DialContext,
		ResponseHeaderTimeout: lb.timeout, 
		TLSClientConfig:       &tls.Config{InsecureSkipVerify: true},
	}

	ctx, cancel := context.WithTimeout(r.Context(), lb.timeout)
	defer cancel()
	r = r.WithContext(ctx)

	errored := false
	proxy.ErrorHandler = func(rw http.ResponseWriter, req *http.Request, err error) {
		errored = true
		b.Alive.Store(false)
		lb.metrics.BackendErrors.Add(1)
		lb.metrics.Failed.Add(1)
		http.Error(rw, "backend unavailable", http.StatusBadGateway)
	}

	proxy.ServeHTTP(w, r)

	if !errored {
		lb.metrics.Success.Add(1)
		elapsed := time.Since(start)
		lb.metrics.LatencyMu.Lock()
		lb.metrics.Latencies = append(lb.metrics.Latencies, elapsed)
		lb.metrics.LatencyMu.Unlock()
	}
}

// ─── Helper ───────────────────────────────────────────────────────────────────

func percentile(sorted []time.Duration, p float64) time.Duration {
	if len(sorted) == 0 {
		return 0
	}
	idx := int(float64(len(sorted)-1) * p / 100.0)
	return sorted[idx]
}

// ─── main ─────────────────────────────────────────────────────────────────────

func main() {
	addr := flag.String("addr", ":8080",
		"address the load balancer listens on")

	backendsFlag := flag.String("backends", "http://localhost:8081",
		"comma-separated list of backend URLs")

	healthInterval := flag.Duration("health-interval", 1*time.Second,
		"how often to probe backend /health")

	backendTimeout := flag.Duration("backend-timeout", 800*time.Millisecond,
		"backend request timeout")

	flag.Parse()

	// Build backend list
	lb := &LoadBalancer{timeout: *backendTimeout}
	for _, raw := range strings.Split(*backendsFlag, ",") {
		raw = strings.TrimSpace(raw)
		if raw == "" {
			continue
		}
		u, err := url.Parse(raw)
		if err != nil {
			log.Fatalf("invalid backend URL %q: %v", raw, err)
		}
		b := &Backend{URL: u}
		b.Alive.Store(true)
		lb.backends = append(lb.backends, b)
		log.Printf("[LB] registered backend: %s", u)
	}

	if len(lb.backends) == 0 {
		log.Fatal("no backends configured")
	}

	// Start health check goroutine
	go lb.healthLoop(*healthInterval)

	mux := http.NewServeMux()
	mux.HandleFunc("/lb/health",  lb.healthHandler)
	mux.HandleFunc("/lb/status",  lb.statusHandler)
	mux.HandleFunc("/lb/metrics", lb.metricsHandler)
	mux.Handle("/", lb)

	fmt.Printf("\nLoad Balancer listening on %s\n", *addr)
	fmt.Printf("Backends : %d\n", len(lb.backends))
	fmt.Printf("Health   : every %s\n", *healthInterval)
	fmt.Printf("Timeout  : %s\n\n", *backendTimeout)
	fmt.Printf("  /lb/health   — LB liveness\n")
	fmt.Printf("  /lb/status   — backend states\n")
	fmt.Printf("  /lb/metrics  — counters + latency\n")
	fmt.Printf("  /            — forward to backends\n\n")

	log.Fatal(http.ListenAndServe(*addr, mux))
}
